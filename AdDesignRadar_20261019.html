📊 深度洞察 Executive Summary

本期严格回顾 2026 年 10 月 12—18 日。上周最明确、可追溯的产品信号来自 Figma：10 月 13 日 Figma Make 开始推出 Gemini 4 Argon，10 月 15 日 Config India 公布 Code Layers、Figma Specs、Payload in Figma、Guidelines、Centralized design systems 与更广泛的 Figma MCP 支持。这些变化把广告团队的工作上下文从单个画板扩展到代码、真实内容、设计规范和代理协作。

上周产品更新 · 10/13、10/15设计上下文 / Code Layers / MCP

01. Figma · 从画板工具走向上下文工作台

访问官方来源 ↗
事实与时间边界

官方 Release Notes 显示，10 月 13 日 Gemini 4 Argon 开始在 Figma Make 中推出，并可在模型选择器里使用；10 月 15 日的 Config India 综述公布 Code Layers（将设计帧、GitHub 仓库或网站捕获转为可交互代码原型）、Figma Specs、Payload in Figma、设计库 Guidelines、Centralized design systems 预览以及支持更多合作伙伴的 Figma MCP。官方标注了 open beta、closed beta、preview 等不同状态，不能把它们统一写成稳定生产功能。

行业洞察与广告价值

对广告设计团队，重要变化不是“agent 会写代码”，而是 brief、真实内容、设计规则和交接对象开始被放在同一上下文里。广告素材最容易失控的环节，往往不是创意草图，而是设计师把旧版 Logo、过期 CTA、错误 App 截图和未经确认的文案混在一个文件里。Specs 与 Guidelines 有机会让审稿问题提前暴露，但前提是团队真的维护来源和规则，而不是把一个模糊的品牌 PDF 当作自动合规证明。

🎯 商业实战 · TikTok / Meta

输入：批准的品牌库、真实产品图、真实 App 录屏、已审英文文案、地区免责声明和目标落地页。先在 Figma 中建立 9:16 与 4:5 的受控结构，只允许修改 hook_text、locale、background_asset 三类变量。TikTok 版本检查首帧、字幕节奏和手持感；Meta 版本重排 4:5 主体、静音阅读、CTA 与落地页一致性。Code Layers 可用于交互原型或模拟产品流程，不应被当成真实 App 功能截图；价格、功效、评价和包装文字必须由真实图层或真实录屏承载。

⚖️ 优势、限制、成本与合规

优势：官方能力把设计库规则、跨文件搜索、代码来源、Specs 与 MCP 放进同一产品方向，适合有成熟组件库和多方交接的团队。限制：部分能力仍为 beta 或 preview；AI credits、套餐、GitHub 组织权限、客户文件可见范围和第三方 MCP 数据流需要逐项核对。模型选择更强不代表它能判断广告事实、平台政策或版权归属。

建议与验收：先做 2 个版位 × 2 种语言 × 2 个 hook 的小样，记录错字、旧组件调用、锁定层被改、人工修订时长和 AI credits。若连续两轮违反锁定层或调用过期资产，应回退冻结母版，不扩大自动化。

来源：Figma Release Notes，10/13 与 10/15 条目；查阅日期：2026-10-19。

上周模型接入更新 · 10/13AI 原型 / 产品演示 / 真实数据

02. Figma Make · Gemini 4 Argon 的广告原型用途

查看发布说明 ↗
事实与时间边界

10 月 13 日官方条目说明 Gemini 4 Argon 正在 Figma Make 中推出，所有计划可用；这是模型在 Figma Make 中的接入更新，不等同于 Gemini 模型首发，也不证明所有团队的输出质量和权限完全一致。该条目没有给出广告转化或成片效率数据。

行业洞察与广告价值

Figma Make 更适合把广告中的“产品如何工作”做成可点击的交互原型，让设计师、产品和客户在投放前看到流程，而不是仅看静态截图。它的价值在于减少对功能的想象偏差，尤其适合 SaaS、工具类 App 和电商页面。但原型是解释工具，不是线上产品；没有真实 API、真实库存和真实权限时，漂亮的交互仍可能是假的。

🎯 商业实战 · TikTok / Meta

为一款 App 广告建立一个可点击的 20 秒产品路径：打开首页、触发核心功能、展示真实结果、进入 CTA。用它与真实录屏逐项对照，确认按钮名称、流程顺序和结果页面一致。TikTok 9:16 版本截取最短可理解路径，避免把完整产品导览塞进首三秒；Meta 4:5 版本可以保留更大产品主体和静音字幕。最终投放用真实录屏或经批准的产品演示，不把原型画面伪装成用户真实体验。

⚖️ 优势、限制、成本与合规

优势：快速让非设计角色理解信息架构和交互卖点，适合先验证脚本与镜头顺序。限制：模型可能生成不存在的按钮、数据和反馈；原型中的代码、图片、字体和插件许可要核对，且模型接入不替代真实设备测试。所有“结果”必须回到可验证产品事实。

建议与验收：先做一个核心路径，不做完整 App。通过条件是：客户能在不听解释的情况下完成关键动作；失败条件是任何一步依赖不存在的功能，或录屏与原型差异需要大量口头补充。

来源：Figma Release Notes · Gemini 4 Argon in Figma Make，2026-10-13；查阅日期：2026-10-19。

上周内容更新 · 10/15CapCut AI Design / 概念板 / 短视频编辑

03. CapCut · 内容更新强化“先概念、后生产”

访问官方资源页 ↗
事实与时间边界

CapCut 官方资源页在 10 月 15 日列出多篇编辑指南，包括免费模板、After Effects intro 模板、图文视频和 AI 视频编辑器等内容；10 月 9 日也有 AI 工具和数字营销视频生成器类文章。它们是内容与教程更新，不足以证明 CapCut 在上周发布了新的核心模型或套餐。此前 9 月 16 日发布的 Campaign Concept Board 指南仍是本期最有用的官方制作参考。

行业洞察与广告价值

CapCut 的可用价值更接近“把概念验证、剪辑、字幕和社交版位适配放在同一条低门槛路径”，而不是自动替代 PR / AE。对广告设计师，概念板的关键作用是先比较构图、氛围、产品占比和渠道风险，避免在错误方向上继续精修。教程页能说明厂商建议的工作方式，但不能作为性能、商用授权或投放效果的独立证据。

🎯 商业实战 · TikTok / Meta

输入一条稳定的 campaign proposition、真实产品参考图和三种方向 brief。每个方向只改变构图和情绪，不改变产品事实、价格与 CTA。TikTok 概念板重点看 9:16 首帧、字幕留白和动作节奏；Meta 4:5 重点看产品主体、标题层级和静音阅读。选定方向后，用批准产品图、真实录屏、人工字幕和真实 Logo 重建关键层，再进入剪辑。

⚖️ 优势、限制、成本与合规

优势：入口多、学习成本较低，适合先做小批量方向筛选和短视频粗剪。限制：页面、地区、设备和账号权限可能不同；AI 生成的产品形状、标签、颜色、文字和暗示性功效需要逐项比对。模板和音乐的商用许可不能只看“可用”标签，下载前要确认具体条款。

建议与验收：每次只生成三种方向，每种按可读性、产品准确、版位适配、后期可行性和版权风险评分。若概念板无法帮助团队选择方向，就停止增加生成量，回到 brief 和真实参考资产。

来源：CapCut 官方资源页（10/15 内容条目）；Campaign Concept Board 指南（2026-09-16）；查阅日期：2026-10-19。

04. Midjourney · Thinking Mode 仍适合概念修正

查看官方公告 ↗
事实与时间边界

Midjourney 官方公告日期为 10 月 8 日，早于本期 10 月 12—18 日回顾区间。公告称正在 Alpha 网站测试 Thinking Mode，可对 8.2 生成结果针对物体、布局、人体结构和文字进行再生成；同日 Alpha Changelog 还记录了共享文件夹。由于它不在上周区间，本卡只作近期能力补充，不写成上周更新。

行业洞察与广告价值

Thinking Mode 的实际制作价值在于把第一次未理解 brief 的图拉回到构图与错误修正，而不是证明模型可以直接产出品牌主视觉。共享文件夹降低了候选图传递摩擦，却也扩大了资产暴露和权限管理范围。它更适合 moodboard、场景方向和后期重建参考，不适合未经审核的 Logo、包装和广告事实。

🎯 商业实战 · TikTok / Meta

用真实产品参考图和不含事实承诺的 brief 生成三种构图，固定人物关系、产品占比与背景情绪，只比较版式。Thinking Mode 只修正粗体排版、主体关系或留白。TikTok 9:16 检查首帧与字幕是否冲突；Meta 4:5 检查主体比例和裁切。最终包装、价格、优惠、免责声明和 Logo 用真实资产重建。

⚖️ 优势、限制、成本与合规

优势：适合快速获得多个可比较的视觉方向，并让设计师把后期重建范围提前写清楚。限制：官方明确是测试能力，“更会思考”不是性能保证；共享文件夹不会自动改变非 Stealth 图片的隐私状态，链接权限、个人历史和 Explore 可见性要分别核对。每次重跑都可能增加成本和人工审核。

建议与验收：选 10 张内部概念图做前后对照，记录可用构图数、文字准确率、人工重建时间和隐私风险。若画面更复杂但没有减少后期重建，不用于正式广告主视觉。

来源：Testing Thinking Mode 与 Alpha Changelog - 10/7/26，2026-10-08；查阅日期：2026-10-19。非本期区间更新。

近期能力补充 · 10/02，非上周更新Draft Mode / 环境镜头 / Agent

05. Runway · Draft Mode 适合提前筛掉错误镜头

查看更新日志 ↗
事实与时间边界

Runway 官方更新日志显示，10 月 2 日 Agent 支持 Seedance 2.5 Draft Mode，可生成快速 480p 草稿并在后生成增强；10 月 2 日 Ideogram 4.5 也进入 Runway MCP。两项均早于本期回顾区间，且属于平台工作流与模型接入更新，不等同于模型首发或所有账号拥有相同权限。

行业洞察与广告价值

Draft Mode 的价值是把方向错误前置暴露：先筛镜头运动、构图和光线，再决定是否为一条候选支付增强成本。它特别适合环境镜头和过渡镜头，不适合把产品包装、App UI 或功效结果交给模型生成。Agent 与 MCP 减少了 brief 和候选在工具间搬运，但越方便越需要分离探索资产、批准资产和正式交付。

🎯 商业实战 · TikTok / Meta

输入一张公开授权的环境参考图、一条不含产品事实的镜头 brief，以及后期叠加真实产品的留白位置。先做 4—6 个短草稿，只比较镜头方向和氛围；通过后再增强一条。TikTok 9:16 保留中心视觉和自然节奏；Meta 4:5 重新安排主体与 CTA。包装、售价、功效、App 界面和免责声明必须由真实资产或 PR / AE 图层完成。

⚖️ 优势、限制、成本与合规

优势：把快速探索、Agent 和第三方模型入口组合起来，适合镜头方向多但预算受控的团队。限制：480p 草稿不能保证增强后修复手部、反射、产品比例和动作连贯；外部模型的积分、账号权限、数据处理和商业授权须分别核对。本期未运行付费生成，不提供成功率或节省百分比。

建议与验收：用一个非客户项目比较从 brief 到可交付镜头的总时长、积分、返工和后期合成成本。如果真实产品叠加后的修复成本超过直接拍摄或简单合成，停止把该路线用于主产品镜头。

来源：Runway Changelog，10/02 条目；查阅日期：2026-10-19。非本期区间更新。

⚡ 深度实战：两条上周可执行工作流

以下是编辑设计的制作方案，不是已运行的自动化流程；没有上传客户素材、付费生成或 TikTok / Meta 投放实测。

1
工作流 A：Figma agent / Make → 真实产品演示 → PR / AE 交付输入批准的品牌 guidelines、真实产品图、真实录屏、批准文案和两种版位规格。先用 Figma agent 或 Make 生成结构和交互原型，只开放 hook、语言和背景变量；用真实录屏逐步替换原型中的假数据。导出后在 PR / AE 中重构字幕、节奏、声画和 9:16 / 4:5 构图。人工审核锁定层、事实、版权、字幕、CTA 和落地页；记录 AI credits、修订次数、错误类型和最终交付时间。
2
工作流 B：CapCut 概念板 → Midjourney / Runway 草稿 → 真实资产重建输入一条稳定的 campaign proposition、三种视觉方向、公开授权参考图和不含产品事实的镜头 brief。先用 CapCut 概念板选构图，再用 Midjourney 或 Runway Draft 只筛环境和氛围镜头；通过后将真实产品、包装、App 录屏、字幕和 CTA 放回 PR / AE。TikTok 重点验收前三秒、首帧和字幕安全区；Meta 重点验收 4:5 裁切、静音理解和落地页一致性。任何事实、权限或成本检查失败都停止。

🚨 避坑雷达

风险一：把上周的模型接入、文章更新或 beta 公告写成稳定新产品。本期只有 Figma 的 10/13 与 10/15 条目明确落在回顾区间；CapCut 的 10/15 主要是资源文章，Midjourney 10/08 和 Runway 10/02 在区间外。采购、报告和对外宣传应分别记录模型首发、平台接入、文章日期、账号可用性和实际测试日。

风险二：把上下文、原型和草稿当成真实广告证据。Figma Make 的交互路径、Midjourney 的概念图和 Runway 的低分辨率草稿都可能包含不存在的产品事实。发布前仍要核对真实产品、价格、功效、人物与音色授权、地区声明、落地页和平台政策；生成工具能减少探索成本，却不会自动补足证据。

💎 上周专属资产

资产 A：上下文受控的广告原型 Prompt

适合在 Figma Make 或类似原型环境中验证产品叙事；不允许把原型冒充真实产品录屏。

Create a clickable prototype for [PRODUCT] using only these verified inputs: [APP SCREENS], [APPROVED FEATURES], [APPROVED CTA], and [BRAND GUIDELINES]. Show one believable user path from [USER GOAL] to [VERIFIED RESULT]. Do not invent buttons, data, prices, testimonials, performance claims, or product screens. Mark every placeholder as PROTOTYPE ONLY. Create variants for TikTok 9:16 and Meta 4:5, keeping the product path unchanged. Return a handoff list: real screen required, claim to verify, missing asset, and what must be recorded from the live product.

资产 B：概念方向到正式资产的验收 Prompt

适合对 Midjourney、Runway 或 CapCut 生成的候选做人工复核前整理。

Review this draft against the approved source package for [CAMPAIGN]. Check product geometry, packaging text, logo usage, price, claims, CTA destination, aspect-ratio crop, subtitle accuracy, voice and image rights, AI disclosure, and landing-page consistency. Separate CONCEPT-ONLY elements from VERIFIED elements. Do not infer approval from visual similarity. For every mismatch, state: severity, required real asset, owner, and whether the draft should be stopped or rebuilt.

📘 上周总结 Weekly Review

回顾 10 月 12—18 日，最明确的行业信号不是又一个“自动做好广告”的模型，而是创意工具开始把上下文、代码、设计规范、真实内容和交接过程放到同一生产链中。Figma 的上周更新最值得优先验证；CapCut 的内容更新适合补充概念板与社交剪辑方法；Midjourney 和 Runway 则应继续作为受控探索工具，而不是未经核验的最终资产来源。

建议优先级：先用一个真实 App 或电商项目测试 Figma 的规则遵守和产品路径准确性，再用 CapCut 选三种概念方向，最后用 Midjourney / Runway 只生成不承载事实的环境候选。完整记录错版、返工、权限、成本、真实资产替换量和最终审片时间，再决定是否扩大采购。上周的工具更新可以改变制作入口，但不能替代品牌控制、真实证据和版位级验收。
